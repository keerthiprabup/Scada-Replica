Denial of Service IDLE

ℹ️ Attack Overview

The DoS attack spawns multiple threads to aggressively open Modbus TCP connections and send junk requests. This exhausts the RTU's connection pool, causing it to drop legitimate SCADA traffic and resulting in a "TIMEOUT" state on the HMI.

Replay Attack IDLE

ℹ️ Attack Overview

Modbus TCP lacks sequence numbers or cryptographic signing. This attack captures the current state of a critical register and continuously writes it back in an aggressive loop. This prevents the SCADA Master from executing legitimate control commands (e.g., trying to close a breaker will immediately be overridden).

False Data Injection IDLE

ℹ️ Attack Overview

FDI targets Holding Registers (sensors/measurements) rather than Coils (actuators). By injecting extreme values, the attacker tricks the HMI into displaying false critical alarms or forces automated logic (like the Isolation Forest IDS) to react unexpectedly.

Normal Data: { "Feeder_Load": 45, "Voltage": 230 }
Spoofed Data: { "Feeder_Load": 9999, "Voltage": 0 }
